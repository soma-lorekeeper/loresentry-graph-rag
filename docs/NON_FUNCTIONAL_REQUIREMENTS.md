# GraphRAG 비기능 요구사항 명세서

## 1. 목적과 적용 범위

데이터 무결성·격리·복구·자원 제한·품질 평가·유지보수·운영에 필요한 조건을 정의한다.
기준은 2026-10-13 로컬 코드이며 운영 환경의 성능·보안·가용성을 측정한 문서가 아니다.
기능 범위와 구현 상태의 의미는 [기능 요구사항 명세서](FUNCTIONAL_REQUIREMENTS.md)를 따른다.
현재 코드로 확인한 한도와 운영자가 아직 결정하지 않은 목표를 구분한다.

## 2. 데이터 무결성과 접근 경계

`store=False`는 해당 모델 요청 옵션이며 서비스 전체의 비보존·보안 정책을 뜻하지 않는다.
S3 bucket/prefix 검사와 프로젝트 ID 검증도 사용자 인가를 대신하지 않는다.

### 현재 한도와 기본값

다음은 현재 지원 한도·설정 기본값이다. 처리량·지연 SLO가 아니며 바이트·문자·토큰을 혼용하지 않는다.

| 대상 | 현재 기준 | 적용 의미 |
|---|---|---|
| 변경 문서 | 요청당 최대 20개 | 비활성 변경도 포함. `max_changed_documents`로 더 낮출 수 있다. |
| ACTIVE 본문 | 문서당 최대 5,000 Unicode 코드 포인트 | 입력·추가 조회 모두 검사. `max_input_chars`로 더 낮출 수 있다. |
| 관계 탐색 | `max_depth` 기본 1, 허용 0∼3 | 관련 문서 선택 범위. 기본 `max_documents=40`은 추가 선택 문서 예산이며 변경 입력 20개와 별개다. |
| 문맥 | `max_context_chars` 기본 480,000 코드 포인트 | JSON 문맥 검사 및 최종 instructions+context 검사. 모델 토큰 한도도 별도로 적용한다. |
| 청크 | `chunk_chars` 기본 1,000 코드 포인트 | 원본 구간 한도. 겹침 기본 0, 허용 범위 `0 ≤ chunk_overlap_chars < chunk_chars`. |
| 모델 호출 | `max_model_calls` 기본 40 | 요청 내부의 최초·보완 호출 합계 예산. 두 단계 기본 경로는 계획 1회·작성 1회·전체 보완 최대 1회다. v5·v6 비교 경로는 호출별 보완 최대 2회. 평가 CLI 기본 상한 18회와 구분한다. |
| 사실 | 호출당 최대 100개 | 집계 상한은 요청 호출 예산에 비례. statement 500자, action·surface 각각 200자. |
| 신규 설정 | 요청당 최대 20개, 이름 최대 200자 | 본문은 요청의 `max_input_chars` 이내. 기존 수정 본문·관계 설명도 이 한도를 검사한다. |
| S3 객체 | 객체당 기본 16,777,216바이트 | 읽기·쓰기 모두 적용하며 설정으로 변경 가능. ACTIVE 본문 문자 수와 별개다. |
| Neptune timeout | 기본 10초 | HTTP 클라이언트 timeout이며 `/health/db` 전체 응답 시간의 상한은 아니다. |
| S3 timeout | 연결 10초, 읽기 60초 | 팩토리 설정. SDK 총 시도 횟수 1회. |
| 평가용 모델 설정 예시 | timeout 240초, 입력 240,000·출력 32,768·문맥 272,768토큰 | `.env.example` 값이다. 앱 전역 기본값·제품 성능 보장이 아니며 실제 모델 호출은 명시적 조립이 필요하다. |

모델 어댑터는 instructions·context·출력 스키마의 UTF-8 바이트 길이와 추가 여유를
보수적 입력 토큰 추정치로 사용한다. 정확한 tokenizer 계측이나 처리시간 상한을 뜻하지 않는다.
출력 예산 초과·불완전 응답은 정상 후보로 수용하지 않는다.

| NFR-016 | 코드 품질 검사와 배포 산출물 식별을 유지해야 한다. | CI가 린트·포맷·테스트 성공 후 이미지를 빌드·게시한다. 이미지에 commit 식별 정보를 기록하고 실행 컨테이너는 비루트 사용자로 동작한다. | 구현: Python 3.12·고정 의존성·CI·Docker 설정. 현재 운영 배포 결과는 미확인 |

기존 실제 모델 평가 결과는 [품질 기록](migration/refresh-quality.md)에 있다.
최근 용어 정의·입력/출력 예시 변경에는 로컬 계약 검증과
[출처 관찰 평가](migration/refresh-quality.md#출처-표현-관찰-2026-10-13)를 수행했다.
소설 5화 수정·6화 추가에는 [단일 호출 관찰](migration/refresh-quality.md#소설-변경-관찰-2026-10-13)을
수행했으며 보완의 출처 검증 통과와 정보 누락에 따른 품질 실패를 구분했다.
단일 조건의 측정이며 변경 전후 품질 비교는 아직 없다.
프롬프트 버전 문자열이 같다는 이유로 과거 측정값을 현재 문구의 성능으로 사용하지 않는다.
평가 로그·Markdown은 운영 모니터링, 경보, 분산 추적의 구현을 대신하지 않는다.

## 6. 운영 전 결정·검증할 조건

프로젝트는 Gateway를 통한 클러스터 내부 접근을 전제로 한다. 해당 배포 경계·네트워크 정책·
실제 IAM/TLS는 이 저장소의 코드 검사만으로 확인하지 않았으며 운영 연동에서 검증해야 한다.

다음 항목에는 현재 합의된 수치 또는 운영 구현이 없다. 임의의 목표를 명세의 확정값으로 두지 않는다.

| 항목 | 확정해야 할 조건 | 현재 상태 |
|---|---|---|
| 가용성·장애 복구 | 서비스별 SLO, RTO/RPO, job 임대 만료·복구 책임, 장애 시 사용자 상태 | 미정·운영 검증 필요 |
| 처리 성능·확장성 | 진단·생성·검색별 지연 백분위, 동시 요청·처리량, CPU/메모리 한도, 큐 적체·백프레셔 | 미정. 현재 생성은 내부 동기 호출이며 요청 내 모델 호출도 순차 실행 |
| 그래프·색인 최신성 | 확정 이벤트부터 반영까지 목표 지연, 준비 상태·revision/이벤트 순서 기준 | 미정·동기화 미구현 |
| 모델·검색 품질 | 평가 자료의 대표성, 역할 오류·환각·누락 허용 기준, 검색 정확도·근거 품질 합격 기준 | 미정. 등록 사례 검사는 있으나 제품 품질 목표는 없음 |
| 비용·재시도 | 요청·프로젝트별 금액/토큰 예산, timeout 재호출 비용, 재시도 횟수·간격·DLQ·운영 경보 | 일부 호출·토큰 제한만 구현. 금액 예산·운영 정책은 미정 |
| 자료 보존·접근 | request/context/result와 평가 원문 보존 기간, 삭제·만료 순서, IAM·암호화·감사·인가 계약 | 미정·운영 검증 필요. 결과 복구에는 request manifest가 필요 |
| 서비스 연결 | Content 본문 변환·권한 확인, 사용자 승인 시 revision/관계 재검사, Kafka 중복 수신 처리 | 미연결. 내부 계약·fake만으로 완료 판단하지 않음 |

후속 구현 순서와 선행 결정은 [후속 계획](migration/follow-up.md), 실행·평가 범위는
[검증 계획](implementation/TEST_PLAN.md)을 따른다. 이 문서는 운영 SLA나 새로운 외부 전송 계약을 확정하지 않는다.
