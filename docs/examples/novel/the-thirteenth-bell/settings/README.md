# 열세 번째 종 — 기존 설정 문서

수정 전 5화까지의 자료를 기준으로 작성한 평가용 설정이다. 수정된 5화와 새 6화를
refresh에 전달하기 **전**의 상태를 보존한다. 도윤의 황동 의지는 아직 강철로 바뀌지
않았고, 방문 전달 업무와 강연오는 아직 기존 설정에 없다.

Markdown 파일이 본문 원본이다. `manifest.json`은 문서 ID·revision·분류·이름과 파일을
연결한다. 평가 로더는 제목과 파일 끝 개행 하나를 제외한 본문을 읽어 Content 조회
fake에 넣고, 이름을 독립 필드 `title`과 호환 속성 `properties.name`으로 제공한다.
manifest의 선택적 단일 `alias`는 `properties.alias`로 전달한다. 아래 revision은 평가용 지정값이다.
Content에 업로드하거나 실제 문서를 생성한 것은 아니다.

## 실행과 결과 읽기

Linux 호스트의 `loresentry-graph-rag` 저장소 루트에서 실행한다. 먼저 원격 호출 없이
파일 로딩·선택·검증·보고서 생성을 확인한다. 출력 폴더는 새 경로를 사용한다.

```bash
.venv/bin/python -m scripts.evaluate_refresh \
  --suite novel-settings --env-file .env.example \
  --trial settings-check-1 --output .evaluation/settings-check-1 \
  --repeat-saved
```

유효한 키·모델 설정을 `.env`에 준비한 뒤 실제 응답을 평가하려면 다음처럼 실행한다.
신규 탐색 1회와 기존 대상 8개의 수정 호출을 분리하여 최대 9회 유료 호출을 요청한다.
자동 재시도는 하지 않는다.

```bash
.venv/bin/python -m scripts.evaluate_refresh \
  --suite novel-settings --live --env-file .env --max-calls 9 \
  --trial settings-live-1 --output .evaluation/settings-live-1
```

`report.md`에서 입력 원문과 기존 설정을 펼쳐 보고, 제안 diff·실패·사용량을
확인한다. 제안별 근거는 보고서에 표시하지 않고 원본 JSON에 보존한다.
`novel-settings.json`에는 실제 사용한 설정 스냅샷과 검사 결과가 저장된다.
설정 파일을 편집하면 fingerprint도 바뀐다. 과거 `novel` suite의 재생 응답은 이 확장
suite에 사용할 수 없다.

오프라인 비교용 [expected-with-settings.json](../../../refresh/novel/expected-with-settings.json)은
기존 설정 3개 수정, 강연오 인물 생성 1개, 도윤–해주 및 6화–강연오 관계 2개를 제시한다.
신규 후보는 첫 호출에서만 생성하며 강연오를 기존 설정 파일에 미리 넣지 않는다.
이 값은 사람이 작성한 제한된 기준선이며 실제 모델 품질을 검증한 결과가 아니다.
실제 모델이 추가로 타당한 설정·관계를 발견할 수도 있으므로 기대값과의 불일치를
곧바로 오류로 판단하지 않고 원문과 비교한다. 반대로 자동 검사 통과도 내용 전체의
정확성을 보증하지 않는다. 기대값 밖의 설정 보존·새 사실 발명은 사람이 확인해야 한다.

평가에서 위 고정 후보는 필수다. 창고·기억 반환소·봉인 유리통·강연오 기억 반환 이벤트는
허용 후보이며 생성 개수를 강제하지 않는다. 등록된 허용 이름·문서쌍 외의 신규 설정이나
관계는 검토 필요로 표시한다. 이름 표기나 의미상 관계가 타당해도 기준에 등록되지 않으면
사람 검토가 필요하다. 미확인 항만 비밀시설은 금지 후보로 지정했다.
필수 수정·생성·관계, 내용 보존·금지 어구 검사 실패는 종료 코드 1,
미등록 추가 후보만 있으면 2, 자동 검사 통과는 0이며 CLI와 보고서는 같은 판정을 쓴다.
이 어구 검사는 의미적 동치나 사실 전체의 정확성을 판정하지 않는다.
