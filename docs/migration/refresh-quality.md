# Refresh 품질 개선과 검증

2026-10-11 키 교체 후 실제 OpenAI 호출을 확인하고, 직접 작성한 가상 소설의
수정 5화·신규 6화와 기존 설정 8개로 refresh를 평가했다. API가 응답해도 후보 검증이나
내용 추출이 실패할 수 있으므로 통신 성공과 갱신안 품질을 구분한다.

현재 생성 계약은 구조화 사실을 요구한다. 아래 v3~v7 실행과 469개 테스트는 당시의
검증 기록이며, 현행 계약의 실제 호출 결과나 회귀 검사 수를 대신하지 않는다.

## 변경한 생성·검증 계약

- 모델은 출처의 문자 위치를 계산하지 않고 서버가 제공한 마커를 선택한다.
  개별 사실의 `source`는 `{"marker":"C0001"}`만 담으며 한 사실은 한 마커를 선택한다.
  어댑터가 해당 마커의 전체 원문 quote·revision·구간을 복원한다. 구간 크기는 요청의
  `chunk_chars`(기본 1,000자) 한도를 따른다. 알 수 없는 마커와 모델이 덧붙인 발췌·
  인용문·위치는 거절하며 정확한 원문 검증은 유지한다.
- 모든 제안은 `fact_ids`로 구조화 `facts`를 참조한다. 사실은 행위자·수령인·대상,
  원문의 행동 표현, 확실성·일부/전체·시점과 짧은 문장을 갖는다. 역할 표면과 행동 표현은
  선택한 마커의 quote에 있어야 하며 문장에는 모든 역할 표면이 포함되어야 한다.
  사실 문장은 500자, 행동·역할 표면은 각각 200자까지이며 원문 의미를 보존해 요약할 수 있다.
  명시 제목·이름·별칭과
  맞지 않는 행위자·수령인 문서 참조는 거절한다. 관계의 설명과 근거는 서버가 참조 사실로
  만들며 모델이 별도로 반환하지 않는다. 유효한 미사용 중간 사실은 최종 결과에서 제외한다.
- CHARACTER·WORLDVIEW·LOCATION·ORGANIZATION·ITEM·EVENT의 생성 기준을 명시했다.
  주요 신규 인물은 장소·이벤트 본문의 언급으로 대신하지 않는다. 유형별 개수를 강제하지 않는다.
- Content의 독립 `title`과 단일 `properties.alias`를 문맥과 중복 판단에 반영한다.
  기존 설정의 이름·별칭 목록을 제공하며, 다른 문서의 본문 언급을 독립 문서로 간주하지 않는다.
- 기존 본문의 낡은 현재 속성을 먼저 수정하고 다른 내용을 보존하도록 했다. 과거와 현재,
  일부 회복과 전체 회복, 기록자와 결정자, 물건별 속성을 구분한다. 승인자·운반자·수령인을
  분리하고, 반환자가 없는 수령 사실은 행위자를 비운다. 장부의 완료 표시를 실제 수령 완료로
  확장하지 않는다. 승인 대상 사건·행동은 대상 역할에 유지하며 직접 승인받은 사람이
  명시되지 않으면 수령인은 비운다. 이름으로 사실을 참조할 때는 이름과 행동을 함께 담은
  마커를 선택하고 원문 별칭을 정식 이름으로 바꾸지 않는다. 익명 담당자의 정체는 주변 인물로 추정하지 않는다.
- 기존 관계쌍은 담당 호출 하나에 배정하고 허용 쌍을 입력에 열거한다. 한 제안의 양방향 키가
  연결 하나를 표현하므로 같은 쌍의 역방향 원소를 추가하지 않는다. 범위 밖·충돌 제안은 거절한다.
- `SelectionSettings.separate_discovery=True`는 신규 탐색 전용 호출과 기존 설정 수정을
  분리한다. 탐색 호출의 기존 수정은 거절한다. 확장 소설 평가에 적용하며 대상 8개는 총 9회다.
  기본값 `False`는 기존 호출 방식을 유지한다. 과거 저장 바이트에는 새 기본값을 추가하지 않는다.

후보 스키마는 `refresh-candidate-v5`, 프롬프트는 `refresh-prompt-v11`, S3 결과는
`refresh-result-v3`다. 결과 JSON은 사실과 제안의 `fact_ids`, 공통 근거 사전의
`evidence_refs`, 실제 검증에 사용한 후보 버전을 보존한다. 상세 계약은
[갱신안 입력·결과 계약](proposal-contract.md#근거와-결과-검증)을 따른다.

실제 OpenAI 어댑터는 현재 후보·프롬프트 버전만 생성한다. 과거 후보 v1/v2의 전체 구간과
v3의 마커 응답, v4/p8·p9·p10의 `source:{marker,excerpt}`, 결과 v1/v2는 명시적인
읽기 호환 경로로만 취급한다. 과거 v4 사실 발췌는 원문에서 유일하게 일치하는 500자 이하
구간으로 읽으며 현행 v5 출력에는 발췌 필드를 허용하지 않는다. 평가 재생은 저장된
입력 fingerprint·대상과 허용된 버전 조합을 확인하고 원본 후보 버전으로 검증한다.
사실이 없는 과거 고정 후보도 이전 계약의 흐름 확인에만 사용한다. 이 경로의 성공을
현재 v5 생성이나 구조화 의미 검사 통과로 보고하지 않으며 live 검증을 완화하지 않는다.
과거 재생과 버전 조건은 [OpenAI 어댑터 기록](openai-adapter.md#설정버전예산)을 참고한다.

## 초기 실제 호출에서 발견한 문제: v3~v7

각 실행은 같은 소설 원문과 확장 설정을 사용했지만 프롬프트·문맥·호출 분리가 달라졌다.
반복 표본의 평균이나 일반적인 정확도 비교가 아니다. 모델은 `gpt-5.6-luna`다.

| 실행 | 실제 호출 | 결과와 보완 |
| --- | ---: | --- |
| v3 프롬프트 / v2 후보 | 1 | API 완료 뒤 `INVALID_EVIDENCE`. 문자 위치 계산을 출처 마커 선택으로 변경 |
| v4 프롬프트 / v3 후보 | 8 | 개별 후보는 검증됐지만 호출 간 같은 관계의 설명이 충돌. 문서쌍 소유권 도입 |
| v5 프롬프트 / v3 후보 | 3 | 담당 범위 밖의 관계로 `INVALID_RELATION_SCOPE`. 허용 쌍을 명시하고 탐색 분리 |
| v6 프롬프트 / v3 후보 | 1 | 신규 관계의 정·역방향 중복으로 `CONFLICTING_PROPOSALS`, 주요 신규 인물 누락. 한 쌍 한 원소와 인물 대조 보강 |
| v7 프롬프트 / v3 후보 | 9 | `PROPOSED`. 기존 수정 7개·신규 6개·관계 41개. 필수·내용·원고 보존 검사 통과, 미등록 추가 후보·관계는 검토 필요 |

v3부터 v6까지의 실패 실행은 최종 제안을 모두 폐기했다. 출처 마커 일치만으로 본문 의미가 맞다는 뜻은
아니다. 중간 후보에서 기존 황동 속성의 수정 누락, 유리통 속성을 상자에 옮긴 설명,
조합장의 기록을 결정 권한으로 확장한 표현을 확인해 프롬프트와 검토 조건을 보완했다.

v7에서는 강연오가 독립 인물로 생성됐고, 도윤의 황동 설명이 강철로 수정되며 한 달 기간과
업무 분담이 반영됐다. 신규 한이경·징수 중지 이벤트처럼 기준에 없지만 원문상 타당한 후보도
있어 종료 코드는 검토 필요인 `2`다. 미등록 후보 4개·관계 31개를 자동 합격으로 처리하지 않았다.
관계에서는 이름 없는 반환 담당자의 행위를 민해주에게 귀속하거나 어머니가 받은 기억을
윤준이 받은 것으로 설명하는 오류가 남았다. 이 관계들은 미등록 관계로 검토 대상이며,
자동 검사 통과를 의미 정확성의 합격으로 표현하지 않는다.
본문에서도 반환소 벽 지도와 귀갓길 지도를 같은 것으로 설명하는 등 원문보다 구체적인
추정이 있어 검토가 필요하다. 어구 보존 검사는 이 차이를 판별하지 못한다.

이번 소설 실행의 입력은 114,357토큰, 출력은 16,124토큰이었다. 모델 어댑터 시간 합계는
135.34초, 호출별 6.79~30.01초이며 운영 지연 보장이나 과금액은 아니다. 원본 JSON과
`.evaluation/refresh-quality-v7-20261011/report.md`는 Git 제외 로컬 산출물이다.

짧은 신규 설정 8사례도 실제 호출했으며 모든 후보가 서버 규칙을 통과했다. 6개 설정 유형을
각각 생성했고, 미확인 시설·원고 내부 명령 사례는 `NO_CHANGE`였다. 최초 자동 평가는
세계관 이름 `해무시의 기억세`를 필수 이름 `기억세`와 달라 누락으로 판단했다.
기대 후보는 유지하고 해당 fixture의 명시적인 허용 이름 별칭을 등록했으며, 필수·금지·본문·
관계 끝의 비교에 같은 별칭을 적용한다. 같은 정체성의 후보 본문도 모두 검사하여 금지 내용이
다른 별칭에 가려지지 않게 한다.

세계관 사례만 새 요청으로 1회 재실행해 `해무시의 기억세`가 자동 검사에 통과하는 것을 확인했다.
최초 8사례의 기록은 변경하지 않았으며, 추가 인물·장소·원고 연결이 있는 사례는 계속 검토
대상이다. 원본 보고서는 `.evaluation/refresh-quality-v7-new-20261011/report.md`, 세계관
재실행은 `.evaluation/refresh-quality-v7-worldview-20261011/report.md`에 있다.

v7 개선을 마친 당시 전체 pytest는 469개 통과했고 Ruff lint·format과 `git diff --check`를 통과했다.
출처 마커 오류 거절, 제목·별칭 보존, 관계 소유권·충돌, 탐색 호출의 수정 금지,
호출 예산, 과거 저장 바이트·재생, S3와 OpenAI SDK의 로컬 HTTP 동작을 회귀 검사했다.
오프라인 기본 6사례는 7회, 확장 소설은 9회, 과거 기본 응답 재생은 7회로 자동 검사에 통과했다.

## 현행 구조화 사실 평가

독립 `semantic` 평가 자료는 다음 6사례이며 전체 실행 계획은 16회다. 인물 이름과
문장 순서를 바꾼 역할 사례, 익명 담당자 사례를 포함한다. 아래 호출 수는 사례별 계획이다.

| 사례 | 비교하는 구조화 사실 | 계획 호출 |
| --- | --- | ---: |
| `semantic-roles` | 승인자·승인 대상, 운반자·수령인, 일부 반환 | 3 |
| `semantic-roles-reordered` | 이름·문장 순서가 달라도 같은 역할 구분 | 3 |
| `semantic-partial-recipient` | 실제 수령인과 미수령인, 일부/전체 | 3 |
| `semantic-record-and-consent` | 과거 완료 기록, 현재 미전달, 동의 후 승인 계획 | 3 |
| `semantic-object-properties` | 물건별 라벨·봉인 귀속과 포함 관계 | 2 |
| `semantic-anonymous-attribution` | 익명 전달자·방문객과 주변 인물의 행동 분리 | 2 |

평가기는 등록한 행동·이름 표현, 문서 참조, 확실성·범위·시점과 해당 사실을 참조한
제안의 종류·대상을 비교한다. 사실이 응답에 있다는 것만으로 제안이 맞다고 판정하지 않는다.
알려진 역할·상태의 불일치는 실패이며, 미등록 표현이나 추가 사실은 검토 대상으로 남긴다.
등록 기준이 모두 일치해도 `source_entailment`는 사람 검토 대기이며 자유 본문도 사람
검토가 필요하다. 원문이 사실 문장을 의미적으로 뒷받침하는지와 본문 전체가 정확한지는
문자열 포함 검사로 증명하지 않는다.

2026-10-11 현행 v11/v5를 실제 모델로 16회 호출했다. 6사례 모두 서버 규칙을 통과해
`PROPOSED`로 저장됐다. 원문과 결과를 대조해 승인자·운반자·수령인, 은서의 일부 반환과
건우의 미수령, 익명 전달 담당자와 방문객, 물건별 라벨·봉인을 확인했다. 미등록 신규
설정·관계·사실 표현은 자동 합격으로 올리지 않았다.

승인 대상은 사람 또는 그 사람의 운반 사건으로 구조화할 수 있으므로 명시적 대체 프레임을
추가했다. 대상 물건의 확인된 문서 ID를 사건의 참조로 쓴 경우도 비교한다. 다른 인물·물건,
잘못된 승인자·확실성·시점은 계속 실패한다. 대상 인물이 빠진 사건은 일치로 확정하지 않고
검토 대상으로 남긴다. 이를 통해 상우의 승인 예정 사실에서 발생한 recipient 불일치를
잘못된 수령인으로 단정하지 않고 구조화 연결 미확인으로 분류했다. 원고·기대 본문과 모델
후보는 바꾸지 않았다. 최초 기록은 `.evaluation/semantic-live-v11-20261011`, 추가 모델
호출 없이 수정한 평가기로 다시 판정한 기록은
`.evaluation/semantic-live-v11-reassessed-20261011/report.md`에 있다. 재평가 후 등록된
구조화 기준의 불일치는 없지만 6사례 모두 검토 필요다.

사람 검토에서는 부정이 짧은 action 대신 statement에만 남은 사실, 대상·동의 조건이
분리되어 구조화 연결을 확인할 수 없는 승인 사실, 명시적 전체 표현 없이 일부 사실에
`extent=COMPLETE`를 붙인 주석을 확인했다. 해당 본문에 전체 회복 표현을 추가한 것은
아니지만 구조화 범위 값의 과잉은 남아 있다. 등록된 기준이 모든 주석을 검사하는 것은 아니다.
실제 16회 호출의 입력은 110,015토큰, 출력은 20,204토큰, 어댑터 시간 합계는
197.62초다. 한 번의 표본이며 일반적인 정확도·지연 보장이나 과금액을 뜻하지 않는다.

긴 소설은 같은 설정으로 두 번 실행했으며 각각 첫 호출과 두 번째 호출에서
`INVALID_FACT`로 실패했다. 첫 실행은 강연오의 직업 사실에 다른 원고 구간의 마커를
선택했다. 두 번째 실행은 기존 인물 본문의 사실에 신규 원고 마커를 붙이고, 원문의 행동
표현을 요약한 값도 반환했다. 자동으로 근거를 바꾸거나 제안 범위를 확대하지 않고 결과를
폐기했다. 자료는 `.evaluation/refresh-quality-v11-20261011/report.md`와
`.evaluation/refresh-quality-v11-repeat-20261011/report.md`에 보존했다. 이 결과는 긴
원고의 출처 연결·원문 행동 표현 선택이 아직 안정적이지 않다는 한계이며, v7보다 생성
성공률이나 의미 정확도가 높아졌다고 결론낼 수 없다. v7에는 없던 엄격한 사실 검사를
적용했으므로 결과 상태만으로 같은 품질 척도를 비교할 수도 없다.

현행 오프라인 기본 6사례·7회, 확장 소설 1사례·9회, 독립 의미 6사례·16회와 과거
기본 응답 재생·7회는 저장 결과 재사용을 포함해 자동 검사에 통과했다. 고정 후보와 과거
재생의 성공은 실제 모델 품질 측정이 아니다.

최종 전체 pytest는 619개 통과했고 Ruff lint·format과 `git diff --check`를 통과했다.
현행 마커 전체 복원, 과거 v4 발췌 읽기, 잘못된 역할 참조와 사실 참조 주입,
호출 간 사실 ID 충돌·예산, 관계 설명의 사실 일치, 저장 결과 참조 손상, 사건 프레임의
평가 오탐과 오인물·상태 오류를 회귀 검사했다. 로컬 HTTP의 OpenAI·S3 SDK 검사도 포함했다.

## 평가 실행과 결과 읽기

Linux 호스트의 저장소 루트에서 실행한다. 출력 경로는 새 디렉터리를 사용한다.

```bash
.venv/bin/python -m scripts.evaluate_refresh \
  --suite novel-settings --env-file .env.example --max-calls 9 \
  --trial quality-check-1 --output .evaluation/quality-check-1 --repeat-saved

.venv/bin/python -m scripts.evaluate_refresh \
  --suite novel-settings --live --env-file .env --max-calls 9 \
  --trial quality-live-1 --output .evaluation/quality-live-1

.venv/bin/python -m scripts.evaluate_refresh \
  --suite semantic --env-file .env.example --max-calls 16 \
  --trial semantic-check-1 --output .evaluation/semantic-check-1 --repeat-saved

.venv/bin/python -m scripts.evaluate_refresh \
  --suite semantic --live --env-file .env --max-calls 16 \
  --trial semantic-live-1 --output .evaluation/semantic-live-1
```

`--live`가 없는 명령은 사람이 정한 고정 후보로 흐름을 검증하며 모델 품질을 측정하지 않는다.
`--live`는 유효한 키로 소설 최대 9회, semantic 최대 16회 유료 호출한다.
자동 재시도는 없으며 예산 부족은 호출 전에 거절한다.
신규 유형별 추출과 미확인 정보·원고 내부 명령은 `--suite new-settings`의 8사례로 별도 점검한다.

평가는 필수·허용·금지 설정, 필수 수정과 관계, 남아야 할 내용과 사라져야 할 어구를 검사한다.
종료 코드와 Markdown은 같은 판정을 사용한다. `0`은 등록된 자동 검사 통과,
`1`은 실행·규칙·필수 후보·내용·구조화 기준 불일치, `2`는 미등록 추가 설정·관계·
구조화 사실이나 표현의 검토 필요다. `0`이어도 자유 본문과 원문 의미의 사람 검토는 남는다.
이름이 다르지만 타당한 후보도 미등록이면 검토가 필요하다. 기준을 맞추기 위해 실제 출력을
기대값으로 바꾸지 않는다.

각 출력 폴더의 `report.md`에는 diff·신규 설정·관계·검사·응답 시간·사용량이 있다.
제안별 근거는 표시하지 않으며 JSON에 보존한다. 기존 제안 본문은 diff와 중복하지 않고
EVENT는 이벤트로 표시한다. 보고서 생성은 추가 모델을 호출하지 않는다.

## 검증의 범위

실제 평가에서 OpenAI만 운영 서비스를 호출한다. S3·Content·관계 조회·작업 상태·Kafka는
fake다. 로컬 HTTP 통합 테스트는 실제 SDK·직렬화·복구 동작을 확인하지만 운영 연결을
검증하지 않는다. 전체 프로젝트 설정 목록을 조회하는 Content 연동도 구현하지 않았으므로
중복 방지는 현재 로드된 문서 범위다.

프롬프트의 정답·오답 예시는 원본 평가 소설의 특정 이름이나 정답을 넣지 않은 별도 자료다.
독립 6사례와 이름·순서 변경은 일부 오류의 재발 여부를 확인하는 범위이며, 이 사례들에서의
성공을 다양한 소설의 일반 성능으로 확장할 수 없다. 어구 검사와 출처 일치도 의미 정확성,
신규 후보의 완전성을 보증하지 않는다. 최종 후보를 원문과 대조하는 검토가 필요하며 운영
문서 적용은 Content의 사용자 확정·revision 재검증 단계에 남아 있다.
